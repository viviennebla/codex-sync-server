# 蹬了吗：人物外观与逐帧 PNG 规范 v1

## 目标与边界

新人物全部使用透明逐帧 PNG，不再渲染旧 Emoji/CSS/SVG 小人。Emoji 仅作为用户主动启用的头部文字覆盖层，绝不转换为 SVG。与 usage、榜单、拖拽位置、身份解耦。原头像字段保留为用户资料，不等于新像素人物头部。

## 合同

- 当前人物为 helmet-commuter，规范画布 128×100，透明背景，朝右；序列内所有 PNG 的画布必须完全一致，不允许逐帧裁剪或居中。
- /riders/frames/manifest.json 声明 schema_version、默认 preset、heads 的 PNG 资源，以及各交通方式的 frames、fps、pack/plain 两套序列。图片资源 URL 属于服务器静态资源白名单，用户不能提交自由路径。
- 每张人物主体帧不含头部，头部独立以与角色同画布对齐的 128×100 PNG 叠加，可随人物状态自动切换 neutral/happy/focused/tired，或锁定一个表情；Emoji 换头使用 DOM 文字覆盖，不依赖 SVG。
- 带背包和无背包提供相同帧数的两套素材。这样动作制作不需要浏览器计算肢体关节或用 CSS 重新拼骨架。
- 骑行状态、步行状态分别逐帧输出。适配其他载具时先制作其专属载具和坐姿 PNG，切勿复用自行车骨架假装正确；其他载具尚未有 PNG 的情况下中性步行作为明确的临时画面，不显示旧 SVG 车辆。
- 所有行走与载具帧采用相同场景锚基准：world canvas、ground line 和 head origin。未来推荐分层导出角色 pose frames 与 vehicle frames，并通过一个简单的锚点偏移组合；不应把单帧骨架关节计算重新带回来。

## 美术素材新增 SOP

1. 先确定角色视觉母版和右向轮廓，载具需要定义接触区域与地面线。
2. 在 Aseprite 或其他绘画软件制作逐帧画面，建议每状态 6–12 帧、约 6–12 FPS，以视觉验收为准。不要让 Agent 仅通过旋转腿部生成所谓的新动作。
3. 导出透明 PNG 原尺寸序列：如 helmet-commuter/walk/pack/00.png 到 05.png；不允许改变画布、逐帧自动 trim 或用图集的 UV 坐标手动配准。
4. 把文件加入 manifest 和服务器静态 allowlist；运行素材检测，确保资源存在、尺寸一致、实际 alpha、无路径穿越。
5. 通过 /me 选头部和背包，首页验收 bike/walk、表情变化、拥挤赛道、375px、reduced-motion，并记录截图。视觉不达标则不发布。
6. 只有请求量成为瓶颈时才在构建期自动生成图集；编辑端持续以独立 PNG 帧为源。

## 本轮实现及后续

本轮自定义提供像素头盔/Emoji 头、表情模式和背包开关；用户选择保存到 rider_appearance，并同步到公开 riders 展示字段。首版 PNG 从原部件导出作架构烟测，**并非新绘制的高质量逐帧动画**。骑行、步行有 PNG；其余四种交通方式尚未提供新 PNG，先中性走路占位。新增人物才需要添加新 preset 目录、配置入口和测试；当前无任意第三方自上传服务。

旧 rider-runtime.js 和旧 SVG 源文件暂留仓库用于对照及素材导出，但首页不加载旧运行时，新角色外观没有旧版视觉回退。最终清理可在素材全面覆盖所有载具后独立做。
